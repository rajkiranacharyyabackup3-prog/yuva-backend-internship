This report proposes a REST API for a small online shop. It covers the assignment's main resources—products, users, orders, and inventory—and identifies visitor, customer, and administrator actions. Customers can manage their own profile and orders; administrators can manage the catalog and stock. Each order item keeps a snapshot of the product name, SKU, and price so later catalog edits do not change an existing order.

The proposed backend is Java with Spring Boot and PostgreSQL. The API uses /api/v1 and an OpenAPI 3.0.3 contract to describe endpoint behavior before implementation. PostgreSQL is selected because an order and its inventory reservation must succeed or fail together. During order creation, the server reads current prices, checks stock, and writes the order and reservation in one transaction. The client cannot set the price. If stock is unavailable, the order is rejected without leaving partial records. JWT bearer tokens, role checks, ownership checks, input validation, and consistent error responses are included in the design.

The report contains functional requirements, endpoint methods and data, request and response examples, HTTP error codes, resource and order-flow diagrams, and a staged implementation roadmap. The current model assumes an initial India launch: prices are INR in paise and delivery addresses use country code IN. That assumption should be revisited if the intended market differs. Payment processing, tax rules, shipping-provider integration, and fulfillment are outside scope because the Week 1 brief does not define them. This is a design proposal; the Java service has not yet been implemented.
