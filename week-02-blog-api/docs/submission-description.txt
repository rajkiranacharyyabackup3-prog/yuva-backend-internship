This Week 2 report describes a working REST API for a blog platform, moving from the Week 1 design exercise into backend implementation. The project uses Java 21 and Spring Boot, with Spring MVC for HTTP endpoints, Spring Data JPA for persistence, Flyway for versioned database setup, and H2 as a local relational database. A PostgreSQL profile is also included for environments where PostgreSQL is available.

The API supports user registration and create, read, update, and delete operations for posts and comments. The report lists the routes, their purpose, and whether each is public, authenticated, or limited to the resource owner. Registration normalizes usernames and email addresses, validates submitted fields, and stores a BCrypt password hash. API responses do not expose the hash. Database constraints enforce unique usernames and email addresses and maintain the links between users, posts, and comments. Invalid input, duplicate account values, missing records, unauthenticated requests, and owner permission failures receive consistent HTTP statuses and JSON error responses.

The submission includes the source project, Flyway migration, integration tests, setup instructions, a data relationship diagram, and this Word report. The automated test suite checks registration, validation, post and comment CRUD, authentication, owner permissions, and missing-resource responses using an in-memory H2 database. A separate cURL smoke check was also run against the live application using file-backed H2. Account and post creation returned 201, the public comment list returned 200, comment editing returned 200, and comment deletion returned 204. The PostgreSQL profile is documented but was not run in this environment; the verified run path uses H2.
