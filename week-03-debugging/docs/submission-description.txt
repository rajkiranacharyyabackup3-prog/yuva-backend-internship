This report documents a controlled debugging exercise on the Week 2 blog API, which uses Java 21, Spring Boot, Spring Data JPA, Flyway, and H2. The Week 3 assignment brief called for simulating and fixing defects, but it did not include a separate buggy starter project. For that reason, this work was carried out in an isolated Week 3 copy. The Week 2 project folder remains unchanged.

The report records five issues found in the controlled version: owners were blocked from editing their own posts and comments, other users could pass the ownership check, account email uniqueness did not handle capitalization consistently, the comments route returned an empty list for a post that did not exist, and listing posts caused extra SQL queries to load authors. Each issue is tied to its observed response or query behavior, its cause in the service or repository layer, and the correction made in the Week 3 copy.

Seven focused regression checks were run against the seeded defects and reproduced the expected failures. After the fixes, the existing API integration tests and the new regression tests completed with 11 tests, no failures, no errors, and no skipped tests. The query-count regression check uses Hibernate statistics and verifies a post list containing five different authors. The accompanying project ZIP contains the source, test code, setup instructions, and debugging notes. The report is limited to this local exercise; it does not claim a production security audit or a test of a separate company-provided codebase.
