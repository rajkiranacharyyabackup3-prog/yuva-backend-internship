This report presents the Week 5 integration and pipeline work for the blog API. The application uses Java 21, Spring Boot, Spring MVC, Spring Data JPA, Flyway, and an in-memory H2 database for automated tests. A new integration test sends requests through the API and security layers. It checks that an unauthenticated write is rejected, an authenticated user can create a post, a later request can read the saved post, a different account cannot edit it, invalid post input returns a validation error, and an unknown post returns a not-found response.

The CI workflow is stored in the repository under `.github/workflows/week5-integration-cd.yml` and included in the Week 5 project folder. It checks out the code, sets up Java 21, runs Maven verification, and uploads the packaged application JAR. A dependent job downloads that artifact and copies it into a temporary staging directory. This demonstrates how a tested build can move into a deployment stage without connecting to a production server or storing cloud credentials.

The local PowerShell simulation was run from the Week 5 folder. It completed the full Maven verification, including five tests with no failures, and confirmed that the packaged JAR could be copied to the staging directory. The report includes the test scope, workflow sequence, and run instructions. A GitHub-hosted Actions result will be available after the workflow is committed and pushed; the local simulation is not presented as a remote CI run. The ZIP contains the source, integration test, workflow copy, simulation script, setup notes, and report.
